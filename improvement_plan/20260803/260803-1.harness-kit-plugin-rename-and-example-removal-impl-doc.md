## 1. 목적과 결정 사항

이 계획은 선행 사용자 스킬 정비와 두 개의 후속 파괴적 변경을 안전하게 수행하기
위한 작업 지침이다.

1. `pre-commit` 스킬을 제거하고 `commit` 스킬을 Codex·Claude의 명시적 Git 커밋
   행동 계약에 맞게 강화한다.
2. 현재 `ai-agent-harness` 플러그인의 설치 정체성을 `harness-kit`으로 변경한다.
3. marketplace 식별자를 `ai-agent-harness`에서 `hb9397`로 변경한다.
4. Git remote와 plugin provenance의 repository URL을 `hb9397/harness-kit`으로 정합화한다.
5. 새 로컬 checkout 기준 경로 `C:/Plugin_Workspace/harness-kit`을 사용하고
   machine-specific 절대 경로를 생성 metadata에서 제거한다.
6. 루트 보호 자산 `example/`을 외부 examples 저장소로 이관한 뒤 현재 저장소에서 제거한다.

최종 설치 표면은 다음과 같다.

### 1.1 이름 선정 이유

`harness-kit`을 선택한다. 짧고 kebab-case 검증 규칙에 맞으며, 선행 `pre-commit`
제거 후 19개 사용자
스킬이 제공하는 설계·구현·검증·문서화 흐름을 특정 모델이나 한 가지 산출물에
가두지 않는다.

| 후보 | 판단 |
|---|---|
| `harness-kit` | **선정**. 범용적이고 설치 표면이 짧으며 확장 가능 |
| `project-harness` | 의미는 명확하지만 일반 명사 조합이라 브랜드 식별성이 약함 |
| `workflow-harness` | workflow에 치우쳐 문서·품질·스킬 포트폴리오를 충분히 표현하지 못함 |
| `agent-workbench` | IDE·실험 도구로 오해할 가능성이 있음 |

### 1.2 호환성 정책

plugin ID와 qualified install 문자열은 사용자 설치 계약이므로 이번 변경은 공개
설치 표면의 breaking change다. `0.2.2`의 manifest, archive, tag를 덮어쓰지 않고
`0.3.0`으로 승격한다. 기본 정책은 별도 legacy alias를 만들지 않는 hard cutover다.

기존 사용자는 다음 순서로 이동한다.

```text
기존 ai-agent-harness@ai-agent-harness 제거
→ marketplace hb9397 갱신
→ harness-kit@hb9397 설치
→ 새 세션에서 skill 호출 확인
```

legacy alias를 병행하면 두 plugin ID와 두 cache 경로를 계속 검증해야 하므로 이번
계획에는 포함하지 않는다. alias가 필요해지면 별도 호환성 계획으로 분리한다.

   기존 `v0.2.2` archive·baseline·historical audit에는 보존된다.

## 3. 기준선과 영향 범위

### 3.1 현재 플러그인 정본과 repository identity

이름은 다음 정본과 생성물에 중복되어 있다. 문자열 전역 치환을 하지 않고 정본을
먼저 수정한 뒤 생성기를 통해 산출물을 재생성한다.

| 계층 | 현재 위치/값 | 목표 조치 |
|---|---|---|
| source constant | `maintainer/skills/harness-plugin-maintainer/scripts/plugin_common.py`의 `PLUGIN_ID`·`PLUGIN_ROOT_REL` | `harness-kit`, 파생 root |
| builder constant | `build_plugin.py`의 `MARKETPLACE_NAME` | `hb9397` |
| repository constant | `build_plugin.py`의 `REPOSITORY_URL` | `https://github.com/hb9397/harness-kit` |
| Git remote | `.git/config`의 `remote.origin.url` | `https://github.com/hb9397/harness-kit.git` |
| manager skill 정본 | `maintainer/skills/harness-plugin-maintainer/**` | 실제 사용자 plugin ID만 새 이름으로 갱신 |
| manager projection | `.agents/skills/**`, `.claude/skills/**` | sync generator로 재생성 |

| release evidence | `maintainer/plugin/{release,cli-smoke,install-verification}.*` 등 | 새 ID·qualified ID·archive 반영 |
| 사용자 문서 | `README.md`, `.user-docs/**` | 설치·호출·업데이트·제거 명령 갱신 |

현재 `0.2.2` 기준 archive SHA-256은 다음과 같이 보존한다.

```text
plugins/ai-agent-harness-0.2.2.zip
016be105eaebf46f164641946c1705edbf1b70bed7a3bf4aff661a6e0814d27c
```

현재 checkout 이동은 `.git/config`에 `core.worktree`가 없으므로 Git object와
branch history에 영향을 주지 않는다. 다만 `generated_marker()`와 internal
upstream registry의 source URL에 남은 `D:/Dev_Workspace/ai-agent-harness-docs`는
machine-specific 값이므로 새 checkout 기준에 맞추거나 stable repository URL로
정규화해야 한다. build determinism을 위해 새 `C:/Plugin_Workspace/harness-kit`
절대 경로를 다른 generated artifact에 추가하지 않는다.

### 3.4 `commit-workflow` 행동 기준과 upstream/reference 정책

`commit`을 특정 외부 스킬의 복제본으로 관리하지 않는다. Codex·Claude의 공식 Git
동작에서 확인되는 공통 행동과 이 저장소의 명시적 local policy를
`commit-workflow`라는 behavior contract로 관리한다. 공식 제품이 공개하지 않은
세부 알고리즘은 제품 보장으로 표현하지 않고 `local-policy` 또는
`runtime-observation`으로 분리한다.

공식 관찰 출처는 다음과 같다.

| source id | 공식 기준 | 추적 방식 |
|---|---|---|
| `openai-codex-commit-behavior` | Codex 기본 지침·AGENTS.md·approval/sandbox·review·customization 문서 | 문서 URL + watched path commit SHA + 관찰한 `codex-cli` 버전 |
| `anthropic-claude-code-commit-behavior` | Claude Code headless commit 예시·built-in Git instructions·permission·hooks·attribution·changelog | 문서 URL + checked_at + 정규화 content hash + 관찰한 Claude Code 버전 |
| `conventional-commits` | Conventional Commits 1.0.0 메시지 문법 | specification URL + 문서 버전 |

핵심 URL은 다음과 같이 고정한다.

```text
https://github.com/openai/codex/blob/2cf2a6a844f1fc2ddd489c8a67fa8bc2f59a6f3d/codex-rs/protocol/src/prompts/base_instructions/default.md
https://code.claude.com/docs/en/headless#create-a-commit
https://code.claude.com/docs/en/configuration
https://code.claude.com/docs/en/permissions
https://code.claude.com/docs/en/hooks
https://www.conventionalcommits.org/en/v1.0.0/
```

현재 관찰 버전은 `codex-cli 0.146.0`, `Claude Code 2.1.220`이다. 버전·공식 문서
경로·changelog에서 `git`, `commit`, `attribution`, `permission`, `hook`,
`includeGitInstructions` 관련 변경이 관찰되면 자동 반입하지 않고 behavior contract
의미 검토 후보로 올린다. 네트워크/API 오류가 발생하면 마지막 accepted 관찰을 지우지
않고 `stale`로 표시한다.

registry schema는 `behavior_contracts`와 `target.behavior_contracts`를 지원하도록
v1.1로 확장한다. behavior-only source는 `target.local_skills`에 직접 매핑하지
않으며, contract가 `consumers.skills: ["commit"]`와 문서·검증 consumer를 가진다.
각 contract claim은 다음 class 중 하나를 가진다.

- `official-documented`: 공식 문서·공식 저장소가 직접 설명한 사실
- `local-policy`: 이 저장소가 안전·품질을 위해 추가한 규칙
- `runtime-observation`: 특정 CLI 버전과 fixture에서 관찰한 결과

필수 local policy는 명시적 커밋 요청 전 실행 금지, 의도한 범위만 stage, unrelated
변경 보존, staged diff 재검토, 기존 hook 정상 실행, `--no-verify`·amend·push·tag의
별도 요청 필요, commit 후 SHA/status/show 검증이다. 사용자 프로젝트의 실제 테스트
명령은 저장소별로 다르므로 commit 스킬이 임의의 전체 테스트나 pre-commit 정규식
스캐너를 강제하지 않는다.

Codex·Claude smoke는 같은 임시 fixture에서 status/diff/stage 경계·메시지·hook·사후
검증을 확인하되, 결과는 제품 간 동등성 선언이 아니라 `runtime-observation`으로만
기록한다. 공식 `commit` 스킬·plugin 파일을 복사하거나 특정 skill source를
upstream으로 삼지 않는다.

### 3.5 기존 식별자 잔존 범위와 파일 분류

구현 전에 다음 패턴을 저장소 전체에서 검색하고, 각 hit를 `live`, `generated`,
`test-fixture`, `historical`로 분류한다. `ai-agent-harness`를 단순 전역 치환하지
않으며, live 항목은 새 정본으로 갱신하고 generated 항목은 generator로 재생성한다.

| 분류 | 확인·갱신 범위 | 처리 원칙 |
|---|---|---|
| 사용자 스킬 원본 | `skills/**`의 SKILL·template·prompt·eval에서 `/ai-agent-harness:`, plugin 경로·설치명 참조 | 사용자 호출 예시는 `/harness-kit:`으로 갱신하고, 사용자 프로젝트에 생성되는 `.docs`·`AGENTS.md`·`CLAUDE.md` 계약은 변경하지 않는다 |
| 관리자 스킬 정본 | `maintainer/skills/harness-plugin-maintainer/**`, `maintainer/skills/skill-portfolio-maintainer/**`의 설명·reference·script·eval·template | plugin ID, qualified ID, repository URL, User-Agent·temp prefix를 live 기준으로 갱신하고 fixture의 외부 예제 URL은 보존한다 |
| 관리자 projection | `.agents/skills/**`, `.claude/skills/**` | 직접 편집하지 않고 `sync_manager_projections.py`로 재생성·`--check` 검증한다 |
| 생성 plugin | `plugins/ai-agent-harness/**` | builder로 `plugins/harness-kit/**`를 재생성하고 runtime skill namespace·metadata·lock·NOTICE를 대조한다 |
| marketplace·설정 | `.agents/plugins/marketplace.json`, `.claude-plugin/marketplace.json`, `.gitattributes`, `.git/config`, `NOTICE` | marketplace·path·repository URL을 갱신하고 old archive path 규칙은 보존 필요성을 확인한다 |

## 5. 전역 안전 규칙

- 이 문서 작성 시점에는 이름 변경과 root `example/` 삭제를 수행하지 않는다.
- `example/`은 보호 자산이므로 외부 clone 검증과 별도 파괴적 변경 승인 전에는
  `Remove-Item`, `git rm`, 이동을 실행하지 않는다.
- `0.2.2` archive와 `v0.2.2` tag는 immutable 기준선으로 취급한다.
- `ai-agent-harness` 문자열을 전역 치환하지 않는다. repository URL,
  historical plan, old archive, migration note인지 live plugin identity인지 파일별로
  분류한다.
- `AGENTS.md`와 `.user-docs/**`가 새 경로·설치명을 설명하기 전에는 root 제거를
  완료로 표시하지 않는다.
- `origin` URL은 `https://hb9397@github.com/hb9397/harness-kit.git`로 확인할 수
  있지만 token을 URL에 저장하지 않는다. `user.name`·`user.email`은 commit identity와
  push authentication을 혼동하지 않도록 별도로 점검한다.
- `core.worktree`·hook·include 설정이 새 checkout을 절대 경로로 묶고 있지 않은지
  확인한다.
- `commit-workflow`의 official-documented, local-policy, runtime-observation을
  섞어 제품 보장처럼 기록하지 않는다. 공식 문서에 없는 자동 stage·테스트·사후
  검증 알고리즘은 local policy로만 선언한다.
- Phase 1의 source/registry 변경으로 기존 `0.2.2` generated tree에 drift가 생길 수
  있음을 기록한다. Phase 1에서 release-ready나 full build-green을 주장하지 않고,
  identity 재생성 Phase의 targeted gate로 회복을 확인한다.
- 생성물은 `sync_manager_projections.py`, `build_plugin.py`, 검증기에서만 갱신한다.
- 각 Phase는 구현·검증·커밋을 한 묶음으로 완료한다. push·tag·release는 마지막
  별도 승인 전까지 수행하지 않는다.

## 7. 위험·rollback

| 위험 | 조기 신호 | 대응 |
|---|---|---|
| 외부 examples 이관 불완전 | clone hash mismatch | root 삭제 중단, 외부 commit 보완 |
| remote 설정 잔존 | `origin`이 old repository URL을 반환 | push 전 `git remote set-url origin`과 fetch 검증 |
| machine-specific path 잔존 | 다른 checkout에서 generated drift 또는 provenance mismatch | stable URL/relative marker로 정규화 |
| old plugin ID 잔존 | live docs/evidence에 old qualified ID 발견 | old hit 분류 후 live 파일만 정정 |
| generated path drift | build `--check` diff | source constant 수정 후 projection/plugin 재생성 |
| 기존 사용자 cache 충돌 | old/new plugin이 동시에 목록에 노출 | migration 문서와 remove→install 순서 검증 |
| 내부 skill example 손실 | plugin manifest에서 internal path 누락 | root example 삭제를 되돌리고 builder 입력 확인 |
| `.docs` 계약 변경 | `git diff -- .docs` 또는 관련 template diff | 해당 변경 즉시 제거; 사용자 산출 경로는 범위 밖 |
| Desktop/model 증적 부재 | release gate `not-release-ready` | 기술 검증과 readiness를 분리해 상태 유지 |

rollback은 `v0.2.2` tag와 보존 archive를 기준으로 한다. 새 `0.3.0` artifact를
삭제하거나 old tag를 force-update하지 않는다. 외부 examples 저장소 이관이 실패하면
root `example/`은 원래 위치에 남긴다.
