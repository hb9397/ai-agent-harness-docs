# prompts/checklist.md
# 역할: 스킬 생성·고도화 완료 전 자가 검증 체크리스트

---

## 라우팅 표

| 목적 | 실행할 섹션 |
|------|-----------|
| 신규 생성 스킬 점검 | 전체 |
| 기존 스킬 고도화 점검 | [구조] + [토큰] + [안전성] |
| shell·외부 명령 사용 스킬 추가 점검 | [외부 명령] 추가 실행 |
| 병렬 처리 스킬 추가 점검 | [병렬 처리] 추가 실행 |

---

## [구조]

```
[ ] SKILL.md는 흐름(Step 목록·참조)만 담고 있는가?
    → 규칙 내용이 SKILL.md에 직접 서술되어 있으면 prompts로 이동
[ ] prompts 파일이 단일 책임인가?
    → 두 역할이 한 파일에 있으면 분리
[ ] 연계 스킬이 있으면 SKILL.md 상단에 연계 흐름 표시가 있는가?
[ ] 헤더에 name, description, allowed-tools가 모두 있는가?
[ ] allowed-tools가 실제 사용 도구만 선언했는가?
[ ] 헤더에 model: 필드가 없는가? (모델 선택은 사용자/환경에 위임)
[ ] 헤더에 agent: fork가 없는가? (서브에이전트 사용은 STEP 0 질문 게이트로 처리)
[ ] 본문이 Codex 등 타 플랫폼에서도 해석 가능한 중립 서술인가?
    → Claude 전용 기능은 질문 게이트로 분기
[ ] private prompts/templates는 자기 스킬 번들 안에서만 참조하는가?
    → 다른 스킬과의 연계는 공개 스킬명·입출력 계약으로만 표현
[ ] 산출물 경로가 C-2 표준을 따르는가? (해당 시)
    → 스킬 유형별 실제 경로가 다름 (예: design-doc → .docs/context-base/DESIGN.md, context-doc → 루트 CLAUDE.md + .docs/instruction/, impl-doc → .docs/impl-doc/{사용자}/{기능명}.md)
    → 복수앱은 .docs/{앱}/context-base/DESIGN.md, .docs/{앱}-context.md, .docs/{앱}/, .docs/root-context/ 등으로 추가 분기
    → 리팩토링 작업 계획서.md §3-2 C-2 경로 표준 표를 참조할 것
[ ] C-1 확인 단계 필요 스킬이면 STEP 0에 프로젝트 유형 감지 + 사용자 확인이 있는가?
```

**판정 기준**: 전체 통과 → [토큰] 진행 / 미통과 항목 → 즉시 수정 후 재점검

## [토큰]

```
[ ] templates 파일에 예시 데이터가 없는가?
    → 예시는 HTML 주석으로만
[ ] SKILL.md와 prompts 간 중복 내용이 없는가?
    → 동일 내용이 두 곳에 있으면 prompts에만 남기고 SKILL.md는 참조로
[ ] 조건 분기가 있는 prompts 파일 상단에 라우팅 표가 있는가?
[ ] 한 번에 묻는 질문이 3개 이하인가?
[ ] 파일 생성 기본값이 "대화창 출력"이고 저장은 요청 시에만인가?
```

---

## [외부 명령] ← shell·외부 명령 사용 스킬만

```
[ ] allowed-tools에 제한 없는 Bash를 사전 승인하지 않았는가?
[ ] Windows와 POSIX에서 실행 가능한 경로 또는 명시적인 수동 fallback이 있는가?
[ ] 파일 감지를 먼저 하고 존재하는 것만 실행하는가?
[ ] 대용량 출력 명령에 파일·줄·결과 수 제한이 있는가?
[ ] 변경 없을 때 전체 스캔 fallback이 없는가?
    → 변경 없으면 즉시 종료
[ ] git 명령이 --stat / --name-only 등 최소 범위를 사용하는가?
[ ] package-lock.json, yarn.lock 등 lock 파일을 직접 읽지 않는가?
```

---

## [병렬 처리] ← 병렬 sub-agent가 있는 스킬만

```
[ ] 병렬 작업이 실제로 독립적인가? (선행 결과 의존 없음)
[ ] sub-agent 작업 수가 6개 이하인가?
[ ] 2개 이하 관점에 병렬을 쓰고 있지 않은가?
[ ] sub-agent 미지원 환경의 순차 fallback이 명시되어 있는가?
```

---

## [안전성]

```
[ ] 파일 수정·생성 전 사용자 확인 게이트가 있는가?
    → "위 내용으로 파일을 저장할까요? (승인 / 수정 / 취소)"
[ ] 수정 요청 시 전체 재작성이 아닌 해당 섹션만 수정하는가?
[ ] 외부 상태 변경·임의 명령 실행·재귀 위험이 있는 스킬에
    disable-model-invocation이 선언되고 플랫폼별 직접 호출 예시가 있는가?
[ ] 구조 점검·감사 요청에서는 파일을 자동 수정하지 않는가?
[ ] 보호 자산 삭제·이동·교체를 별도 승인 없이 수행하지 않는가?
```

## 안티패턴 빠른 감지표

| 증상 | 안티패턴 | 수정 방향 |
|------|---------|----------|
| SKILL.md에 규칙 표가 있음 | 이중 명세 | prompts로 이동, SKILL.md는 참조만 |
| prompts 파일이 두 역할 담당 | 단일 파일 다중 책임 | 목적별 파일 분리 |
| templates에 실제 값 있음 | 예시 데이터 혼입 | 빈 구조 + HTML 주석 |
| 한 번에 질문 4개 이상 | 질문 남발 | 🔴 2개로 압축 |
| 변경 없어도 전체 grep | Fallback 전체 스캔 | 변경 없으면 즉시 종료 |
| 관점 2개도 sub-agent 분기 | 과도한 병렬화 | 3개 미만은 순차 |
| 결과를 항상 파일로 저장 | 무조건 파일 생성 | 기본은 대화창, 저장은 요청 시 |
