# Harness Kit v0.4.3 릴리스 노트

## 주요 변경 사항

### `harness-kit`으로 이름과 설치 단위 통합

이전 정식 태그 `v0.2.2`의 플러그인 ID는 `ai-agent-harness`였다. 현재 ID, marketplace 항목, Codex·Claude manifest, runtime 경로와 archive 이름은 모두 `harness-kit`으로 통일했다.

기존 설치가 남아 있으면 새 플러그인을 설치하기 전에 이전 항목을 제거한다. 프로젝트에 복사된 legacy skill은 자동으로 삭제하지 않는다. `.agents/skills/**`, `.claude/skills/**`, `skills/**`를 읽기 전용으로 조사해 구버전 복사본, 사용자 수정본, 프로젝트 고유 스킬로 나눈 뒤 사용자가 승인한 항목만 백업·제거한다.

### 사용자 스킬 19종, 에이전트 0개

두 runtime은 다음 사용자 스킬 19종을 동일하게 제공한다.

- 설치·기반: `harness-setup`, `harness-bootstrap`, `git-scoped-account`
- 설계·컨텍스트: `design-doc`, `context-doc`
- 디자인·프로토타입: `ui-ux-pro-max`, `motion-design`, `design-prototype-docs`, `create-prototype`, `frontend-design`
- 구현 계획·검증: `impl-doc`, `impl-fe-be-doc`, `impl-reuse-scan`, `impl-verify`
- 품질·문서: `multi-review`, `commit`, `code-comment`, `doc-audit`, `humanize-korean`

독립 `pre-commit` 스킬과 scanner는 제거했다. 커밋이 필요할 때 사용자가 `commit`을 명시 호출하면 저장소 지침과 변경 범위를 확인하고 기존 hook을 통과한 Conventional Commit을 만든다. `commit`은 push, amend, tag 또는 branch 생성을 자동으로 수행하지 않는다.

### 프로젝트 소유 artifact routing

모든 Markdown producer는 플러그인 내부 경로가 아니라 프로젝트가 소유한 routing 문서를 기준으로 산출물 위치와 인계를 결정한다.

- 단일 앱: `.docs/instruction/artifact-output-routing-instruction.md`
- 복수 앱: `.docs/{앱}/instruction/artifact-output-routing-instruction.md`

복수 앱의 설계 문서, 구현 계획, 프로토타입, 디자인 시스템과 모션 명세는 항상 `.docs/{앱}/**` 아래로 분리한다. Markdown producer는 고정 7종(`harness-setup`, `harness-bootstrap`, `design-doc`, `context-doc`, `design-prototype-docs`, `impl-doc`, `impl-fe-be-doc`)과 조건부 2종(`ui-ux-pro-max`, `motion-design`)이다.

조건부 producer는 기본적으로 대화창에 결과를 보고하고, 사용자가 파일 저장을 명시적으로 요청했을 때만 산출물을 만든다. 문서 윤문은 최외곽 producer가 `humanize-korean` 개선안과 diff를 한 번 제안하며 승인된 변경만 반영한다.

### 쓰기 점검과 외부 artifact 정규화

선택적으로 host-local write guard를 설치하면 Claude와 Codex에서 관찰 가능한 쓰기 요청을 같은 project-owned routing 계약에 따라 점검한다. 기존 정본 문서, 승인된 앱 source, `.docs/_inbox/**`는 허용하고 새 관리 문서에는 경로와 내용 hash에 묶인 일회성 승인 marker가 필요하다.

외부 텍스트는 `.docs/harness/normalize-artifact.ps1 -Plan`으로 G12 제안을 먼저 확인한다. 명시적으로 승인한 뒤에만 UTF-8과 managed marker 기준으로 정본 문서에 반영할 수 있다. JSON, YAML, 이미지와 PDF는 `_inbox` manifest에 hash와 proposal만 기록하며 자동으로 변환하거나 승격하지 않는다.

write guard는 동적 shell 경로, hosted tool, 외부 process의 쓰기를 완전히 차단하지 못한다. 관찰할 수 없는 경로는 차단 성공으로 간주하지 않고 bypass evidence로 남긴다.

### UI/UX와 모션 설계

- `ui-ux-pro-max` runtime과 provenance를 upstream `v2.13.0` 기준으로 갱신했다.
- `motion-design`은 진입·퇴장, 상태 피드백, 타이밍·이징, 접근성, 성능과 reduced-motion 대안을 설계한다.
- 저장을 요청한 디자인 시스템은 단일 앱의 `.docs/design-system/{project-slug}/**` 또는 복수 앱의 `.docs/{앱}/design-system/{project-slug}/**`에 둔다.
- 모션 명세는 위 디자인 시스템 경로의 `motion/{screen-or-component}.md`에 둔다.

### 프로토타입과 제품 UI의 책임 분리

`create-prototype`은 요구사항과 UX를 확인하기 위한 폐기 가능한 HTML·CSS·JS 시안을 만든다.

- 단일 앱: `.docs/prototype/**`
- 복수 앱: `.docs/{앱}/prototype/**`

`frontend-design`은 승인된 앱 source에 유지보수할 실제 제품 UI를 구현한다. 프로토타입 코드를 제품 source로 그대로 복사하지 않고, 승인된 디자인 결정과 화면 명세만 인계해 기존 컴포넌트·토큰·프레임워크에 맞춰 다시 구현한다.

## 설치와 업데이트

### Codex

새로 설치할 때:

```text
codex plugin marketplace add hb9397/harness-kit
codex plugin add harness-kit@hb9397
```

기존 marketplace를 갱신할 때:

```text
codex plugin marketplace upgrade hb9397
codex plugin remove ai-agent-harness@ai-agent-harness   # 이전 설치가 있을 때만
codex plugin add harness-kit@hb9397
```

설치 후 새 task를 열고 `$harness-setup`처럼 `$skill-name`으로 명시 호출한다.

### Claude Code

새로 설치할 때:

```text
claude plugin marketplace add hb9397/harness-kit
claude plugin install harness-kit@hb9397
```

기존 설치를 갱신할 때:

```text
claude plugin marketplace update hb9397
claude plugin update harness-kit@hb9397
```

설치 또는 업데이트 후 대화형 session에서 `/reload-plugins`를 실행하고 `/harness-kit:harness-setup`처럼 namespaced skill을 명시 호출한다. 앱에서는 marketplace를 동기화한 뒤 플러그인을 설치·업데이트하고 완전히 재시작해 새 task/session을 연다.

## 검증 결과와 알려진 제한

다음 자동 검증은 통과했다.

- Codex와 Claude manifest의 ID·버전 일치
- archive checksum과 release metadata 일치
- 19 skills / 0 agents inventory 일치
- packaged upstream의 NOTICE·license·lock 완결성
- `humanize-korean` proposal-only 동작과 보호 token 보존
- 격리된 Codex CLI 및 Claude Code CLI marketplace 등록, 설치, 목록·cache 확인, 제거 smoke

CLI smoke는 설치된 payload와 cache를 확인한 결과이며 실제 모델 호출 성공을 뜻하지 않는다. 현재 남은 수동 증적은 다음 네 인터페이스 모두의 명시 호출, 산출물, 취소 시 원본 hash 보존, 재시작과 새 task/session 확인이다.

- Codex CLI
- Codex 앱
- Claude Code CLI
- Claude 앱

정식 태그 게시와 별개로, 이 수동 증적이 없으므로 저장소 내부 릴리스 게이트 상태는 `not-release-ready`다. `v0.4.3`을 설치한 운영자는 각 인터페이스에서 `$harness-setup` 또는 `/harness-kit:harness-setup`과 `humanize-korean`의 proposal-only 동작을 직접 확인해야 한다.

세부 설치 절차는 [Plugin Installation Guide](../../../.user-docs/Plugin_Installation_Guide.md), 현재 검증 상태는 [release checklist](../release-checklist.md)와 [install verification](../install-verification.json)을 참고한다.
