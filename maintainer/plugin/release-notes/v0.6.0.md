# Harness Kit v0.6.0 배포 후보 안내

`0.6.0`은 프로젝트 문서 루트를 `.ai-docs/`로 전환하고, 문서 쓰기 권한과 로컬 계정
연결 흐름을 현재 정본에 맞춘 배포 후보다. 이전 `.docs/` 프로젝트는 자동으로 섞거나
덮어쓰지 않고 승인형 이관 흐름으로 처리한다.

주요 변경 사항은 다음과 같다.

- `harness-setup`, `harness-bootstrap`과 문서 생성 스킬이 `.ai-docs/` 하나를 현행 문서
  루트로 사용한다.
- `project-write-access`는 서명 정책, 세 Git 서비스용 CODEOWNERS, 참여자 PC의 표준
  Git 훅과 지원되는 AI 쓰기 가드를 관리한다.
- 원격 Git 서비스의 브랜치 보호, 직접 push 제한, 필수 승인과 병합 방식은 프로젝트
  관리자가 별도로 운영한다. 스킬은 관련 설정 API를 호출해 값을 만들거나 바꾸지 않는다.
- `git-scoped-account`와 `project-write-access`의 로컬 등록을 연결해 각 참여자의 현재
  provider·host·계정이 서명 정책과 일치할 때만 `.ai-docs/**` 쓰기 가드를 활성화한다.
- `admin`, `pm-pl`, 앱별 `app-doc-lead`, 표시용 `developer` 역할을 상속 없이 각각
  배정한다. 애플리케이션 소스코드는 이 문서 권한 정책으로 제한하지 않는다.
- `harness-bootstrap`이 확인받은 프로젝트·앱 범위를 `design-doc`과 `context-doc`에
  전달해 같은 범위 질문은 반복하지 않되, 앱 핵심 문서의 별도 쓰기 승인은 유지한다.
- 복수 앱의 `.ai-docs/root-context/AGENTS.md`를 Git 관리 원본으로, 프로젝트 루트
  `AGENTS.md`를 실행본으로 구분한다.
- `context-doc`은 `agent-instruction.md`와
  `artifact-output-routing-instruction.md`를 항상 생성한다.

## 호환성

`.docs/`에서 `.ai-docs/`로의 변경은 공개 산출물 경로 변경이다. 기존 서명 정책이 있으면
`project-write-access`의 `migrate-root-plan`과 `migrate-root`를 사용하고, 두 문서 루트가
함께 있으면 자동 병합하지 않는다.

## 배포 상태

이 문서는 main 배포 후보의 변경 내용을 설명한다. `v0.6.0` tag와 GitHub Release는
아직 만들지 않았으며, 게시된 최신 stable은 `v0.4.3`이다. 새 아카이브를 대상으로 한
Codex·Claude CLI 격리 설치 smoke는 통과했다. 네 인터페이스의 실제 모델 호출과 앱
증적은 관리자 예외 문서에 알려진 검증 한계로 남긴다.
