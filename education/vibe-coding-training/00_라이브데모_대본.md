# D4 · 라이브 데모 대본 — 개인용 TODO 데스크톱 앱 (Electron)

> ③덱 마지막 "데모 진입 표지" 뒤에 이 대본으로 넘어온다.
> 이 문서는 **발표자용 대본**이지 슬라이드가 아니다.
> 소재·기술 스택 확정 근거: `00_교육자료_설계.md` §6-1.
> 작성일: 2026-07-11

---

## 0. 이 데모가 있는 이유 — 한 문장

> **"자연어로 요청 → AI가 설계 `.md`를 먼저 만든다 → 그 `.md`가 산출물의 근거가 된다 → 그래서 재현된다"**
> 를 청중 눈앞에서 30분 안에 목격시키는 것.

이것이 §1 관통 주장("코드 짜는 능력이 아니라 문서 쓰는 능력")을 **머리가 아니라 손·눈으로 체화하는 순간**이다. 데모의 모든 선택(소재·저장 방식·재현 단계)은 이 목적을 따른다.

## 1. 데모 개요

| 항목 | 값 |
|------|-----|
| **소재** | 개인용 TODO 데스크톱 앱 |
| **기술 스택** | Electron + React + TypeScript, JSON 파일 저장, `.exe` 배포 |
| **저장 방식** | DB 없음 — 사용자가 지정한 폴더에 `todos.json` + 주간보고 `.md` |
| **AI 도구** | Claude Code (superpowers 플러그인 설치 · `brainstorming` 스킬 활용) |
| **총 시간** | 30분 (2.5h 기준, flex 구간) |
| **전제 환경** | Node.js 20+, git, Claude Code, superpowers 플러그인 · 사전 설치 완료 |

### 요구사항 (앱이 제공할 것)

1. 계층 TODO — 부모-자식 하위 작업 (`parentId` 방식)
2. CRUD — 생성·편집·삭제
3. 날짜·마감기한·기간 설정
4. 마감 알림 (Electron Notification)
5. **주간보고 `.md` 내보내기** ← 클라이맥스
6. 첫 실행 시 저장 폴더 선택, 이후 폴더 변경 가능
7. 개인용 (공유·동기화 없음)

### 최종 산출물 (데모 끝나면 손에 남는 것)

- `design/todo-app.md` — brainstorming으로 뽑은 **설계 문서**
- `src/` — Electron+React 코드
- `dist/TodoApp-Setup.exe` — 배포 가능한 설치 파일
- `{사용자 폴더}/todos.json` + `{사용자 폴더}/weekly-2026-W28.md` — 앱이 만든 사용자 데이터·주간보고

- [ ] Node.js 20+ 설치·`node -v` 확인

## 3. 4단 대본

### 단계 ① · 환경설정 + 요구정리 (7~8분)

**의도**: "AI에게 코드를 시키기 전에, **의도를 문서로 정리하는 것이 먼저**"임을 청중에게 보여준다. 여기가 §1의 **"질의 능력"** 과 **"맥락 공급"** 이 동시에 등장하는 순간.

#### 3-①-1. 프로젝트 셋업 (환경설정도 자연어로)

**발표자 입력 (Claude Code에)**:
```
demo/todo-app 폴더에서 Electron + React + TypeScript 프로젝트를 시작하고 싶어.
개인 TODO 앱을 만들 거야. 초기 셋업까지만 해줘.
```

**청중에게 짚어줄 것 (구두)**:
> "환경설정 명령어를 외우는 게 아니라, **원하는 걸 문장으로 전달**하고 있다는 걸 봐주세요. `npx create-electron-app` 같은 명령어를 기억할 필요가 없어요."

**예상 결과**: `package.json`, `main.ts`, `renderer/` 폴더 등이 생성됨. 실패해도 상관없음 — 백업 브랜치 있음.

---

#### 3-①-2. brainstorming 스킬로 설계 `.md` 뽑기

**발표자 입력**:
```
/brainstorming

개인용 TODO 데스크톱 앱을 만들려고 해. 다음 요구가 있어:
- 하위 작업(계층) 가능
- 편집·삭제·알림
- 날짜·마감·기간 설정
- 결과물을 .md 파일로 내보내기 (특히 주간보고용)
- DB 안 쓰고, 사용자가 저장 폴더 지정
- .exe로 배포
- 개인용 (공유 X)

설계 문서(design/todo-app.md)를 먼저 만들어줘.
```

**여기가 이 데모의 결정적 순간이다.** brainstorming 스킬은 즉시 코드로 뛰어들지 않고, **AI가 청중에게 되묻는다**:
- "주간보고는 이번 주 완료·진행·다음주 계획 3섹션이 맞나요?"
- "알림은 마감 시각에? 아니면 마감 하루 전에도?"
- "폴더 선택은 첫 실행 시 1회? 언제든 변경 가능?"

**청중에게 짚어줄 것 (구두)**:
> "봐주세요. AI가 저한테 되묻고 있어요. 이것이 **§1에서 말한 '질의 능력'** 입니다. 제가 놓친 요구를 AI가 캐물어서 끌어내고 있어요."

**발표자는 답만 하면 됨**. 답 예시:
- 주간보고 3섹션 OK
- 알림 = 마감 하루 전 + 마감 당일
- 폴더 선택 첫 실행 + 언제든 변경

**산출물**: `design/todo-app.md` — 다음 섹션을 담은 마크다운
- 요구사항 목록
- 데이터 스키마 (TODO 필드: `id`, `parentId`, `title`, `dueAt`, `period`, `notifyAt`, `done`, `createdAt`)
- 저장 구조 (`{userDir}/todos.json`, `weekly-{YYYY-WW}.md`)
- 주간보고 템플릿
- Electron 메인/렌더러 프로세스 책임 분리

**청중에게 보여줄 것**: **에디터에서 `design/todo-app.md`를 크게 띄운다.** 이 순간 청중이 "**아, 코드 나오기 전에 문서가 먼저 나오는구나**"를 체감.

> 💬 **회수 발언**: "지금까지 AI가 만든 건 **코드 한 줄이 아니라 문서 한 장** 입니다. 이 문서가 앞으로 만들 앱의 **근거**가 됩니다."

---

### 단계 ② · 구현 (10~12분)

**의도**: 설계 `.md`가 실제 코드의 근거가 됨을 보여준다.

#### 3-②-1. 설계 근거로 구현 요청

**발표자 입력**:
```
design/todo-app.md 를 근거로, 앱 골격을 만들어줘.
먼저 저장 폴더 선택 다이얼로그 + todos.json 읽기/쓰기 + 계층 TODO 리스트 UI까지.
```

**진행 중 청중에게 짚어줄 것**:
> "제가 '이렇게 저렇게 만들어줘'라고 다시 설명하지 않았어요. **문서 이름을 가리켰을 뿐**입니다. `@design/todo-app.md`를 참조하라고. **이게 §1의 '맥락 공급'** 입니다."

#### 3-②-2. 실행 & 저장 폴더 선택 시연

앱 실행 → 첫 실행 다이얼로그 → 미리 준비한 `Documents/MyTodos` 지정 → TODO 몇 개 추가 (하위 작업 포함).

**청중에게 보여줄 것**: **탐색기 열어서 `Documents/MyTodos/todos.json` 실물 공개.**
```json
{
  "tasks": [
    { "id": "1", "parentId": null, "title": "고객사 교육 자료 완성", "dueAt": "2026-07-15", "done": false },
    { "id": "2", "parentId": "1", "title": "D4 대본 마무리", "done": true }
  ]
}
```

> 💬 **회수 발언**: "DB 없어요. **파일 하나**입니다. 여러분이 손으로 열어볼 수 있어요."

#### 3-②-3. 알림 붙이기 (짧게)

**발표자 입력**:
```
설계 문서대로 마감 하루 전 + 당일 알림을 붙여줘.
```

시연 — 마감 임박 TODO 하나를 데스크톱 알림으로 띄우기. (환경 문제로 안 뜨면 콘솔 로그로 대체)

---

### 단계 ③ · 주간보고 `.md` 내보내기 — **클라이맥스** (5~6분)

**의도**: **§1 관통 주장의 최종 회수 지점.** "결국 결과물은 문서(`.md`)"를 눈으로 목격.

#### 3-③-1. 내보내기 기능 추가

**발표자 입력**:
```
설계 문서의 주간보고 템플릿대로 [이번 주 보고 내보내기] 버튼을 만들어줘.
파일명은 weekly-{YYYY-WW}.md, 저장 폴더에 생성.
```

#### 3-③-2. 실물 공개

- 앱에서 [주간보고 내보내기] 클릭
- **탐색기에서 `Documents/MyTodos/weekly-2026-W28.md` 실물 열기**
- 내용 예시:
  ```markdown
  # 주간보고 · 2026 W28

  ## ✅ 이번 주 완료
  - 고객사 교육 자료 완성
    - D4 대본 마무리

  ## 🔄 진행 중
  - ③덱 pptx 슬라이드 작업

  ## 📅 다음 주 계획
  - Vercel 배포
  ```

> 💬 **최고 강도 회수 발언 (여기서 잠깐 멈춘다)**:
>
> "여러분, 오늘 이 교육의 첫 문장을 기억하시나요?
> **'코드 짜는 능력이 아니라, 문서를 쓰는 능력이 AI 시대의 핵심 역량이다.'**
>
> 지금 우리가 손에 쥔 게 뭡니까?
> **첫째, 설계 `.md` — 앱이 왜 이런지 설명하는 문서.**
> **둘째, 주간보고 `.md` — 앱이 만들어낸 결과 문서.**
>
> 코드는요? 코드는 이 두 문서 사이에 잠깐 있었을 뿐입니다. 지워도 됩니다."

**바로 이어서 단계 ④로**.

---

### 단계 ④ · 재현 (5분, flex — 시간 밀리면 축약)

**의도**: "문서가 있으면 재현된다"를 실제로 보인다. §1 Spine의 완전한 회수.

#### 3-④-1. 코드 통째로 삭제 (담대하게)

**발표자 입력 (터미널)**:
```powershell
Remove-Item src -Recurse -Force
Remove-Item package.json, tsconfig.json -Force
# design/todo-app.md 는 남긴다
```

**청중에게 짚어줄 것**:
> "**코드는 다 지웠습니다.** 남긴 건 단 하나 — **설계 `.md`**."

#### 3-④-2. 문서 하나로 다시 요청

**발표자 입력 (Claude Code에)**:
```
design/todo-app.md 를 근거로 앱을 다시 만들어줘. 같은 스택으로.
```

Claude Code가 **같은 문서를 근거로 같은 앱을 다시 만드는 과정**을 청중이 목격.

> 💬 **최종 회수 발언**:
>
> "다시 만들어지고 있죠? **코드는 사라져도, 문서만 있으면 돌아옵니다.**
>
> 이게 오늘의 결론입니다. AI 시대에 여러분이 남겨야 할 자산은 **한 번 잘 쓴 문서**입니다.
> `.md` 하나가 앱을 재현합니다. `.md` 하나가 팀을 정렬시킵니다. `.md` 하나가 다음 사람에게 전달됩니다.
>
> **그래서 우리는 오늘, `.md` 쓰는 감각을 배웠습니다.**"

#### 3-④-3. (여유 시 · optional) `.exe` 빌드

```
electron-builder로 .exe 산출해줘
```

`dist/TodoApp-Setup.exe` 파일 탐색기에서 공개 → "이걸 그대로 나눠주면 배포 끝입니다."

## 4. 시간 배분 요약

| 단계 | 이름 | 목표 시간 | 밀렸을 때 |
|------|------|:---:|-----------|
| ① | 환경설정 + 설계 `.md` | 7~8분 | 유지 (여기가 § 1 첫 회수) |
| ② | 구현 (저장·UI·알림) | 10~12분 | 알림 생략 가능 |
| ③ | 주간보고 `.md` 내보내기 | 5~6분 | **절대 유지** — 클라이맥스 |
| ④ | 재현 (+ .exe 옵션) | 5분 | 축약 가능 (코드 삭제→"만약 여기서 다시 문서만 남기고 시켰다면" 구두 마무리) |
| 합계 | | **27~31분** | |

**밀리면 순서대로 자르기**:
1. 단계 ④의 `.exe` 빌드 생략
2. 단계 ②의 알림 붙이기 생략
3. 단계 ④를 구두 마무리로 축약
4. **단계 ③은 절대 자르지 않는다** — 잘리면 오늘 교육 전체의 회수 지점이 사라짐.

## 5. 실패 시 롤백 절차

### 5-1. AI 응답 이상 (환각·엉뚱한 파일)
- 즉시 **되돌리는 문장**: "그건 아니고, `design/todo-app.md`만 참조해줘." — 문서를 다시 가리키기.
- 청중에게 오히려 이 순간을 교보재로: "봐주세요, **AI가 헤맬 때 되돌리는 유일한 방법이 문서를 다시 가리키는 것**입니다."

### 5-2. 코드 실행 실패 (빌드 오류)
- 30초 안에 못 잡으면 **`git checkout backup-final`** — 백업 브랜치로 즉시 복구.
- 청중에게: "실무에서도 데모 실패는 있어요. **커밋해둔 문서·코드가 있으면 30초 안에 복구됩니다.**"

### 5-3. 네트워크·플러그인 이슈
- Claude Code 응답 안 오면 → 발표자 노트로 준비한 "예상 응답 스크린샷" 공개 → 설명으로 대체.

### 5-4. 최악의 시나리오 — 라이브 전면 실패
- 완성본 앱 미리 실행해두고 **단계 ③(주간보고 내보내기)만 시연**. §1 회수는 지킨다.
