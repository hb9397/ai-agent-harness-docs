## 1. 한 줄 컨셉

> **브이월드 배경지도 위에 재난 관련 API 레이어를 얹고, shp 파일을 업로드해 주제도로 저장하는 웹 지도 서비스** — 를 자연어 + 설계 `.md`로 만들어 보인다.

**관통 주장과의 연결**: 1안(TODO)이 "누구나 이해하는 도메인"이라면, 2안은 "실무 도메인(GIS·재난)". **같은 하네스(설계 `.md` → 구현)가 도메인이 완전히 달라져도 그대로 작동**함을 보여주는 것이 2안의 존재 이유다.

| 주제도 기능 | **shp 파일 업로드 → 주제도로 저장** (저장 방식은 미정 — §3) |
| 1안과의 관계 | 1안 유지, 2안 병행. 강사는 Codex·Claude 둘 다 사용 |
| 인프라 사전 세팅 | Docker 기반 **PostgreSQL(PostGIS)** · **GeoServer** 컨테이너를 교육생 환경에 미리 구성한다 — **단, 실제 사용 여부는 미정** (§3). "일단 세팅"이 방침 |

## 3. 미정 사항 ❓ (아이디어 수준 — 확정 시 이 문서 갱신)

| # | 미정 항목 | 후보 / 메모 |
|---|-----------|-------------|
| U1 | **재난 API 소스** | (a) 브이월드 제공 재난 관련 레이어 (b) 재난안전데이터공유플랫폼 [safetydata.go.kr](https://www.safetydata.go.kr) (c) 공공데이터포털 [data.go.kr](https://www.data.go.kr) — 키 신청 승인 리드타임 확인 필요 |
| U2 | **shp 저장 경로** | (a) 클라이언트 파싱(shpjs 등) → GeoJSON → PostGIS 저장 (b) GeoServer 업로드·발행까지 (c) 파일 그대로 보관 + 메타만 저장 — GeoServer·PostGIS를 **안 쓸 수도 있음** |
| U3 | **DB 사용 여부** | PostGIS 사용 여부 자체가 미정. 세팅은 해두되 데모 범위에 넣을지는 별도 결정 |
| U4 | **GeoServer 사용 여부** | 동일 — 세팅은 해두되 사용 여부 미정. 안 쓰면 "이런 것도 있다" 소개 수준 |
| U5 | **앱 형태** | (a) 순수 웹앱 (Vite + React) (b) 1안과 대칭인 Electron — 웹앱이 가벼워 유력 |
| U6 | **라이브 범위** | 30분 라이브에 전부는 불가. (a) 사전 스캐폴드 위에 레이어 추가만 라이브 (b) 완성본 시연 + 핵심 구간만 라이브 — 1안과의 역할 분담(§5)과 함께 결정 |
| U7 | **백엔드 유무** | shp 업로드·저장에 백엔드(FastAPI/Express)가 필요한지, 클라이언트 완결로 갈지 — U2·U3에 종속 |

## 4. 아키텍처 스케치 (아이디어 — 확정 아님)

```
[브라우저: React + OpenLayers]
 ├─ 배경지도: vworld API (WMTS/XYZ)      ← 확정
 ├─ 재난 레이어: 재난 API 호출 → 오버레이   ← 소스 미정 (U1)
 └─ shp 업로드
     ├─ (경량안) 클라이언트 파싱 → GeoJSON → 지도 표출 + 저장(U2)
     └─ (확장안) 백엔드 → PostGIS 저장 → (선택) GeoServer 발행 → WMS/WFS 레이어
[Docker: PostGIS + GeoServer]             ← 세팅은 하되 사용 여부 미정 (U3·U4)
```

**교육 관점 권장 기울기**: 경량안(클라이언트 완결)을 기본으로 하고, PostGIS/GeoServer는 "확장하면 이렇게 된다"로 보여주는 쪽이 라이브 리스크가 낮다. — 단 이것도 아이디어이며 확정 아님.
